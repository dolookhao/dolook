# 用户旅程地图不是海报，而是决策工具

> 演示文章｜用于展示博客排版、目录与阅读体验；正式内容待替换。

**导语：** 把触点、动机和障碍放进同一张图，才能找到真正要解决的问题。

## 从真实问题出发

画用户旅程时，我通常把阶段、目标、触点、行为、情绪、障碍和机会并列展示。每一栏都必须有访谈、日志或现场观察支撑，才有实际决策价值。

## 拆解关键难点

旅程地图最有用的时刻是团队对问题排序意见不一致时。它能让大家看到某个节点为什么导致后续流失，以及改动可能影响哪些部门。

## 建立可执行的方案

在资源有限的情况下，应优先修复关键路径上造成最大损失的一个阻碍，再回到数据里验证。

## 总结与实践启发

不要为了好看而追求复杂，能够引导决策的地图才是好工具。
